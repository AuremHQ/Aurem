# RCA — run 4bb45a1a-fa6e-4520-964d-aeb923b107ae (redeploy, launch-pad-237)

## Symptom
Deploy failed at step `build_image`, Cloud Build step #8 `frontend-build-push`.

## Error (verbatim)
```
file:///workspace/frontend/scripts/seo-prerender.mjs:595
if (HARNESS_CONTENT) {
^
ReferenceError: HARNESS_CONTENT is not defined
    at file:///workspace/frontend/scripts/seo-prerender.mjs:595:1
Node.js v24.22.1
error Command failed with exit code 1.
```

## Root cause (confirmed via eph sandbox on this run's source)
`frontend/scripts/seo-prerender.mjs` references the identifier `HARNESS_CONTENT` at lines 595 and 596:
```
595: if (HARNESS_CONTENT) {
596:   const { body, ld, meta } = harnessBody(HARNESS_CONTENT.content, HARNESS_CONTENT.liveStats);
```
`grep -n 'HARNESS_CONTENT'` returns ONLY those two lines — the variable is never declared, imported, or assigned anywhere in the file. In an ES module a reference to an undeclared identifier throws `ReferenceError` at runtime, which aborts the prerender script and fails the frontend build (exit 1).

The script DOES define the related flags it clearly intended to use here:
- `const HARNESS_PAGE_MODE = await resolveHarnessPageMode();`  (line 119)
- `const HARNESS_RELEASE = HARNESS_PAGE_MODE ? await resolveHarnessRelease() : { available: false };`  (line 148)

So this looks like an incomplete refactor: the `/harness` prerender block was wired to a `HARNESS_CONTENT` object (with `.content` and `.liveStats`) that was never fetched/declared.

## This is NOT
- Not a manifest issue (build-frontend-artifacts.sh / Dockerfile / nginx etc. are untouched here — the crash is inside the app's own script).
- Not a missing dependency, not a secret, not a tier/OOM issue, not platform.

## Suggested fix (E1 / source)
Define `HARNESS_CONTENT` before line 595, consistent with the existing flag logic. Options:
1. If the `/harness` snapshot should only render when the feature flag is on and a release is available, resolve the content object (the same way `HARNESS_RELEASE` is resolved) and assign it, e.g.:
   ```js
   const HARNESS_CONTENT = HARNESS_PAGE_MODE && HARNESS_RELEASE.available
     ? await resolveHarnessContent()   // returns { content, liveStats }
     : null;
   ```
   (implement/point `resolveHarnessContent` at whatever source `harnessBody` expects), OR
2. If the harness page content is not ready, guard the block with an existing defined flag and skip it, e.g. replace `if (HARNESS_CONTENT)` with `if (HARNESS_PAGE_MODE && HARNESS_RELEASE.available && HARNESS_CONTENT)` AND ensure `HARNESS_CONTENT` is at least declared (`const HARNESS_CONTENT = null;`) so it never throws.

Either way the identifier must be declared. After the source fix, redeploy — the rest of the pipeline was never reached, so no other change is needed.
