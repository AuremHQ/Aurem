# RCA — Deploy run ec8b48c5-345f-43a1-8948-98cb4849383e (launch-pad-237)

## Summary
The redeploy failed at the **deploy (deploy_k8s)** step. The new backend pod entered **CrashLoopBackOff (early), lastExit=1/Error** because the FastAPI backend crashed on import with a Python **SyntaxError**. The traffic flip never happened — the previous healthy run (`e92c92ce...`) is still serving `https://launch-pad-237.emergent.host`, so the live app is NOT down.

## Root Cause (confirmed)
File **`backend/routers/wrapped.py`**, **line 67** contains a stray leading `9` character before the dictionary key, producing invalid Python:

```
9            "completed_at": {"$gte": start_ts, "$lte": end_ts},  # shipped in period, not created in period
```

The crash chain (from the rollout logs):
```
File "/app/backend/routers/wrapped.py", line 67
    9            "completed_at": {"$gte": start_ts, "$lte": end_ts}, ...
SyntaxError: ':' expected after dictionary key
```
imported via `from routers.wrapped import router as wrapped_router` in `backend/main.py` line 95 → uvicorn fails to load the app → `Backend failed to start at initialization, exiting`.

## Evidence
- `py_compile` of the pulled source in an eph sandbox reproduced the exact error:
  `SyntaxError: ':' expected after dictionary key` at line 67.
- Removing the stray `9` prefix (so the line becomes a normal indented `"completed_at": {...},` entry) makes the file compile cleanly (`COMPILE_OK`), and the surrounding `db.cto_tasks.find(...)` query reads correctly.

## Fix (Code — E1 applies, then redeploy)
In `backend/routers/wrapped.py` line 67, delete the leading `9` so the line reads:
```python
            "completed_at": {"$gte": start_ts, "$lte": end_ts},  # shipped in period, not created in period
```
(Keep the 12-space indentation to match the other keys in the dict.) After the fix, redeploy.

## Not the cause
Not a manifest, tier, secret, DB, or infra issue — the image built fine and the pod scheduled; it is purely a source syntax error in user code.
